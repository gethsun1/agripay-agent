The overrides are compatibility-preserving and must be removed when `@hashgraph/sdk` directly requires patched releases. The two `auditConfig.ignoreGhsas` entries are reachability-based exceptions, not claims that the upstream defects are fixed; remove each as soon as a compatible patched dependency exists. The pinned x402/Hedera major versions were not changed. `pnpm audit --audit-level high` passes with these documented exceptions; plain `pnpm audit` reports only the documented low advisory. Lockfile inspection and a frozen install are CI release gates.

No advisory is considered remediated solely from disappearance in a dashboard: the lockfile, dependency paths, tests, and production builds are the evidence. Revisit the residual `elliptic` item on every Hedera SDK upgrade and track it as a narrowly scoped dependency issue.
